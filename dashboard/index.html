Research note: what this model earns, and what it cannot do

The bounty asks for a radar, not a promise. This page states the model's limits before it states its prices.

How it is tested

The comps are ordered by the day the snapshot began tracking them. Each fold is predicted by a curve fitted only on the comps tracked before it, so no protocol is ever predicted by a curve that has seen it.

What each factor earns

Each row is the same held-out folds with one part of the model removed, and the number is the median error in multiples of the true value: lower is better. The growth multiplier earns its place on price; the maturity factor is not a price factor at all — it ranks how long a protocol has run with no token, and the snapshot records no launch dates to test that against, so it is stated as a stated prior rather than as a fitted one.

What the model does not claim

  • It does not predict that a token is issued, or when. The board ranks protocols whose own token does not exist yet; whether one ever issues is outside the snapshot.
  • It does not price a farmer's share of that token. The snapshot says nothing about how an allocation would be set, so the board states the protocol's value and the plan's cost separately rather than multiplying them into a number the data cannot support.
  • It does not name a protocol. The same function scores every row, and the page recomputes each one from the snapshot's figures and prints how many it reproduced.
  • It is not a price. A wide band is the honest reading of a market where one protocol's token trades at a hundredth of its TVL and another's at its TVL.

The page is drawn with one palette and one type ramp: a dark ink ground, a radar green for the model's own numbers, gold for the house watchlist and blue for tokens already trading. One system font stack, one spacing scale, no webfont, no image, no network.

How the value model works

The snapshot carries no score, no ranking and no signal: deriving them is the work. Every implied value here is arithmetic on the snapshot's own figures. The page recomputes each row from the factors below and prints how many rows it reproduced, so the board, the code and the pixels are one arithmetic rather than three stories.

  1. size curve mcap = 102.297 × TVL0.615 Fitted on the comps: the snapshot's own traded protocols. The exponent says how much more a token is worth for each tenfold of TVL, read off the market rather than assumed.
  2. band low to high The fit's own residual quartiles. The market pays a wide range for the same size, and the band says so.
  3. growth 1 + (7-day TVL change) / 100 × 0.5 Clamped to −60%..+120%, so one bad week cannot decide a rank.
  4. maturity 0.75 + min(days with no token, 730) / 730 × 0.5 The longer a protocol has run without a token, the closer it is to issuing one.
  5. implied TVL0.615 × growth × maturity This entry's own claim about what the token would be worth. Not a quote, and not a promise that a token comes.
  6. coverage 198 ranked, 144 set aside Every protocol in the snapshot that records no token is either on the board or named, with its reason, in the Set aside view.
  7. stability bootstrap The size curve refitted on 200 resamples of the comps: the spread of the exponent and how often the top ten holds.

What if the model were different?

Move a slider and the ranking moves with it. The board above is the model as fitted and shipped; this is the same arithmetic under other settings, so a reader can see how much the ranking depends on the choices.

What the market pays for size

The size curve fitted on the traded protocols, and every pre-token protocol placed on it. A point far above the curve is priced as if it were bigger than it is.
